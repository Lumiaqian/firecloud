## 📖 设计理念与视觉隐喻

「霞光预报」以**天空画笺**为首页设计语言：天空呈现实况，两张错位纸笺分别承载指数判断与事件时刻。

沿用暂选 A「日轮云笺」Logo，全文使用小赖 Regular。浏览器图标使用独立校正的 16/32/48px 小尺寸稿，安装图标使用同源详细稿；浏览器原生标签文字与关闭按钮由浏览器控制。

页头、城市、时段、日期、月相与页脚直接落在天空上。桌面分数笺居左下、时刻笺居右上；手机先读分数，再读右侧时刻笺。天气批注在前、未来七日在后。城市下方固定保留一行带日期的更新时间、简短状态与刷新动作；更新、失败和取消切换均不挪动双笺，仅无记录的首次加载或失败使用独立状态笺。

分数、时刻、批注和七日共用柔软连续的纸缘遮罩、纸纹与轻影，不使用厚边框、锯齿裁切或七格折痕。圈注、引线、括注和铅笔下划线使用设计稿原始素材；七日选中与最高分分别用下划线、开口圈标记，手机横向翻看。

生产素材位于 `assets/paper/`，来自设计系统 `_blobs/` 与画布源稿；`supporting-paper-mask.svg` 和 `paper-grain-wide.png` 是共用纸面，`score-annotations.png`、`home-time-marks.png` 及 `supporting-*.png` 承载笔迹。运行时不依赖设计工具；昼夜纸色按此刻天文计算，雨湿、云影与纸缘接触仅由已确认实况驱动。保存记录的旧天气不驱动粒子与纸面效果，月相仍按当前地点和时刻计算。

## ✨ 核心特性

* 🌅 **多维度霞光光路研判模型**
  * 深度融合高、中、低三层云量遮蔽度。
  * 沿太阳落入/升起方位角，向外延伸 6 个视距采样点（近端、中端、远端与侧翼对照点），精准评估远端光路通透性。
  * 结合空气相对湿度、视距能见度、气溶胶（AOD）、PM2.5 及沙尘指标，测算瑞利散射与余晖衰减。
  * 产出 0–99 经验量表分值，档位文字、行动建议与主题色共用同一组分界：
    * **80–99 极佳**：值得专程等待
    * **65–79 值得追**：值得追这场霞光
    * **50–64 有机会**：可以顺路看看
    * **35–49 一般**：有空可以留意
    * **0–34 平淡**：不建议专程等待

* 🧭 **观赏窗口与影响因素**
  * 事件笺带预报日期，给出观赏窗口（起止与余晖峰值，按当天民用晨昏蒙影推算）与太阳方位；已确认预报的倒计时以窗口开始为准，保存或刷新失败的记录只显示静态预报时刻，不宣称「观赏中」。
  * “天气批注”分云层、空气两组列出真实分项变化，用页边批注指出主要扣分项，可展开理想区间；封顶规则单独说明，缺测项不伪装为实测零值。
  * 未来 7 日按滚动日期范围标出最高分及具体日期，不使用自然周的“本周”表述；手机端横向翻看连续纸条，第 5–7 天标为远期参考。天气请求覆盖当前日起 8 个当地日，避免下一场在明天时第七天超出范围；空气质量按实际可用范围降级。
  * 主卡、逐日卡片与读屏建议共用朝霞／晚霞对应文案，以“可能”“可留意”等措辞表达预报条件，不将红日、云隙光等现象描述为必然发生。

* 🌧️ **真实气象微物理系统**
  * 基于当前实况天气驱动的纯 Canvas/物理运动学粒子引擎。
  * 保留雨、雪、冰雹与侧风粒子；纸缘承接天气，数字和正文不抖动。实况强风进入独立风景，天气切换采用可打断的 650ms 渐变。雷暴不自动闪击，点击纸夹才触发一次局部光效；圈注与纸边分别提供暖光、轻风反馈。页头可关闭动态，系统“减少动态效果”优先；关闭时清理粒子与纸面动效，操作仅反馈文字。

* 🌙 **夜巡月相札记**
  * 真实天文月相算法：实时测算照亮面比例、月龄朔望日、地平仰角、天球方位向。
  * 首页月亮与月相入口仅在地点当前夜间显示，不随所选朝霞／晚霞或预报日期切换。天空月亮还须位于真实地平线上，朔月隐藏光晕；夜间月亮已落时保留月相入口并标明「地平线下」。
  * 达芬奇辉光（地球照）底盘与水墨晕染月海流线，契合手札素描质感。
  * 月相札记的农历日期与观测时间统一使用地点时区；时区未知或无效时回退设备时区。Logo 单击或键盘激活立即打开地点选择。

* **晨昏切换与加载反馈**
  * 同地点切换晚霞、朝霞时保留当前手记与阅读位置，在城市下的状态行说明目标时段及暂留记录，提供取消／重试动作，不新增大卡片或使用全屏 loading；时段标签在成功前保持原选择。
  * 加载期间主卡与详情整体弱化，暂停旧内容交互；数据就绪后一次替换时段、分数与观测数据。
  * 立即切回当前手记时保留原数据新鲜度；过期请求的响应不会覆盖最新选择，有效缓存无需等待网络。
  * 切换失败时保留当前手记并明确提示未能读取的时段；键盘操作与减少动效模式停用切换动画和旋转提示。
  * 选择未来日期后，分数、时间、倒计时、伴随指数和天气批注按该日渲染；天空、纸面天气和月相仍按此刻实况。切换研判视角或刷新同地点、同时段预报时保留选中日期。
  * 切换到其他地点或成功读取另一晨昏时段后，日期回到该时段的下一场事件；失败或取消时段切换时保留原日期。
  * 网络响应和缓存均在采用前校验目标日期的本地分层云量；HTTP 成功但数据缺测也按加载失败处理，不覆盖当前可用手记与缓存。刷新以提交时最新选中日期为准。
  * 缓存年龄由保存时间计算，切换日期或研判视角不会重置数据新鲜度。
  * 缓存、刷新中、刷新失败、切换中与切换失败共用紧凑状态行，更新时间不因操作或切换日期而改变。缓存只标明「天气实况待更新」；成功读取后恢复真实天气和倒计时。极昼极夜与分层云量缺测使用不同提示，不显示伪造的零分。

* 🔒 **本机缓存与第三方查询**
  * 评分在浏览器内计算；最近地点、收藏、预报和界面偏好保存在当前浏览器，不保存城市搜索历史。
  * 城市检索向 Open-Meteo 发送关键词；天气和空气质量查询向 Open-Meteo 发送地点及采样点坐标；设备定位的逆地理编码向 BigDataCloud 发送定位坐标。
  * 收藏可逐一移出；最近地点、收藏与预报缓存可通过清除浏览器的网站数据删除。
  * 地点抽屉固定标题和搜索区，列表独立滚动；输入焦点只加深底线。星标只改收藏，地名才切换地点；最多八处，移出后可撤销。

* ⚡ **纯原生零依赖架构**
  * 零打包构建工具链（无 Webpack/Vite），原生 ES Modules。完整小赖字体约 11.3 MiB，首次访问需下载，随后由 Service Worker 离线缓存；许可证见 `assets/fonts/Xiaolai-OFL.txt`。
  * 全套 PWA Service Worker 离线缓存，离线仍可查看先前手札记录；首次访问带新查询参数的地址时，同源作用域内导航可回退缓存应用壳，资源请求仍精确匹配。安装新版本时绕过 HTTP 旧缓存重新获取预缓存资源，保持离线 HTML 与模块版本一致。

## 🛠️ 第三方气象与地理数据

应用所有测算完全在浏览器前端即时计算，数据直发公开第三方接口：

* **[Open-Meteo Forecast API](https://open-meteo.com/)**：获取高/中/低分层云量、空气湿度、能见度、降水、实况天气与风况。
* **[Open-Meteo Air Quality API](https://open-meteo.com/)**：获取气溶胶光学厚度（AOD）、PM2.5、沙尘等空气质量数据。
* **[Open-Meteo Geocoding API](https://open-meteo.com/)**：城市智能检索、去重与行政区划分。
* **[BigDataCloud Reverse Geocoding API](https://www.bigdatacloud.com/)**：设备 GPS 经纬度逆地址反查。

## 🚀 本地开发与测试

运行本项目无需安装任何第三方 npm 依赖包，仅需现代浏览器与 Node.js 22+（用于测试套件）：

### 启动本地静态服务

```bash
npm run dev
```

启动后在浏览器打开 `http://127.0.0.1:8765/` 即可体验。

### 测试与语法校验

```bash
# 检查全部 JavaScript 模块语法
npm run check

# 运行自动化单元测试套件 (node:test)
npm test

# 串联执行语法校验与测试套件 (部署前必查)
npm run verify
```

### 模块与缓存版本

页面通过 `index.html` 中的 import map 统一钉住各模块版本，Service Worker 预缓存同一组地址。新增或删除 `js/` 下的模块、或发布新版本时：

```bash
# 按实际模块重写 import map 与 sw.js 预缓存列表
npm run sync-modules

# 发布时同时把模块版本与 Service Worker 缓存名加一
npm run sync-modules -- --bump
```

同步脚本收集首页全部外链样式表。`css/sky-letter-tokens.css` 是设计系统令牌的生产快照，仅调整字体相对路径；令牌变更时从源系统重新同步，不分别维护两套数值。字体、Logo 和纸面素材也纳入应用壳预缓存。

本机存储被禁用或预报缓存损坏时，仍可读取和展示在线预报，只放弃持久化。Service Worker 的缓存写入在后台完成，配额或写入失败不阻断成功的网络响应。太阳方向低云缺测时可沿用本地低云参与日轮评分，但批注仍标记「缺测」，不冒充远端实测。

## 🌐 自动化部署

仓库配置了 GitHub Actions 持续集成流水线（`.github/workflows/deploy-pages.yml`）：
每次向 `main` 分支提交代码时，流水线先执行 `npm run verify`，再运行 `npm run build` 生成 `dist/`，只上传该目录至 GitHub Pages，不上传设计源、测试、脚本或仓库文档。

`npm run build` 会重建生成目录 `dist/`，白名单为 `index.html`、`sw.js`、`manifest.webmanifest`、`.nojekyll`、`LICENSE` 及 `css/`、`js/`、`assets/`、`icons/`。新增运行时资源目录时需同步 `scripts/build-site.mjs`。

本地预览发布产物：先运行 `npm run build`，再运行 `python3 -m http.server 8766 --bind 127.0.0.1 --directory dist`。

本轮边界修复通过 89 项测试；浏览器验证禁用存储仍可选城、损坏缓存恢复，以及跨设备时区的农历一致性。发布产物以录制天气响应完成首页与地点弹窗检查；44 个预缓存地址均可访问，设计源、测试、脚本与 README 在发布目录中均返回 404。此检查不代表已部署到线上。
