## 1. 核心设计哲学与审美愿景

### 1.1 实体手札隐喻 (Physical Field Journal)
卡片与控件一律是不透明或近不透明的纸面，不做玻璃拟态（Glassmorphism）；仅弹窗遮罩和天幕上的半透明操作条允许背景模糊，用于保证文字可读。回归有温度、有呼吸感的**“田野气象观测手记（Field Stationery Journal）”**。
- **世界观**：用户手持一本在原野与旷野中记录晨昏天色的气象学者手札。
- **实体材质**：米白和纸票据（Washi Paper Docket）、古典黄铜长尾夹（Brass Clip）、活页手撕齿孔条（Paper Perforations）、朱砂红检验印（Cinnabar Seal）、撕边和纸遮蔽胶带（Washi Masking Tape）与手工水彩试色条（Watercolor Swatch）。
- **自然背景**：背景不再是单调的 CSS 渐变，而是随真实经纬度与时间演变的**双层水彩天幕（Atmospheric Sky Canvas）**，页面实体卡片宛如平铺在浩瀚天色之上的观测记录纸。

### 1.2 核心任务与层级
1. **即时决策**：一目了然回答“下一场霞光值得等吗”。主卡阅读顺序固定为：指数 → 档位与建议 → 事件时间与倒计时 → 评注。指数用档位墨色直接表达好坏，不要求用户读小字。
2. **气象溯源**：随后展开云层分布（低/中/高云）、远端通透度、湿度与能见度等科学线索。
3. **真实感微互动**：让实体卡片与真实自然天气产生微物理共鸣；装饰服务于信息，不与信息争夺注意力。
4. **零构建与极速交付**：保持原生纯静态架构，不引入臃肿框架与重型动画库，保证毫秒级直出。

### 2.1 材质规范细节
- **米白宣纸与圆点网格**：主手记卡片底色采用 `--paper-card-bg`，叠加 `radial-gradient` 呈现 16px 间距的复古点阵底纹，边缘辅以微小的自然倾角（`-0.35deg`）与内阴影漫反射。
- **黄铜长尾夹 (Brass Clip)**：采用双层金属渐变与高光线，位于主手记右上边缘（斜角 5deg）。带有立体夹痕压迹与物理倒影；在不同天气下呈现反光、积雪或火花。
- **手撕齿孔条 (Paper Perforations)**：卡片顶部排布均匀排列的齿孔痕迹，模拟从手记本撕下的活页质感。
- **朱砂印章 (Cinnabar Seal)**：方形双边框篆刻风印章，包含“验”、“测”或地点简字。具有细微的印泥墨渗感与倾角（`-4deg`）。
- **和纸遮蔽胶带 (Washi Tape)**：两端采用锯齿手撕边缘（`clip-path: polygon(...)`），半透明质感，透出底层纸张纤维纹理。
- **水彩试色条 (Watercolor Stroke)**：贯穿于卡片底部的有机色彩带，模拟气象水彩试色效果，颜色严格对应预报档位。

### 2.2 装饰预算
装饰叠加过多会变成噪音，按区块限定：
- **主卡**：齿孔、胶带、黄铜夹、朱砂印章，不再加邮戳水印等额外层。
- **7 日卡片**：小胶带、齿孔、小印章、水彩试色条。
- **影响因素、七日概览、弹窗内容**：纯纸面加细边框与点阵底纹，不加胶带与夹子。
- 区块标题右侧只放有信息量的内容（基准分、本周最佳），不放复述标题的说明文字。

## 3. 颜色语义与指数评价映射

评分、操作、状态与天空氛围分立，杜绝使用单一通用色污染多种语境。

### 3.1 霞光指数档位（唯一档位表）

档位文字、行动建议、朱砂印章、主题档位 `data-tier` 与纸面墨色全部来自 [js/forecast.mjs](../js/forecast.mjs) 中的 `gradeFor`，**禁止在其他地方另写分界**。日轮视角沿用同一组分界，只替换印章文字与建议。

| 指数 | `data-tier` | 档位文字 | 行动建议 | 朱砂印章 | 纸面墨色 | 水彩试色 |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| **80–99** | `epic` | 极佳 | 值得专程等待 | 紫金 · 绝艳霞天 | `--ink-epic` 朱红 | 绯红→暖金 |
| **65–79** | `great` | 值得追 | 值得追这场霞光 | 晴金 · 绚彩可期 | `--ink-great` 琥珀 | 暖金橙 |
| **50–64** | `good` | 有机会 | 可以顺路看看 | 柔光 · 浮云堪赏 | `--ink-good` 暮蓝 | 暮云青蓝 |
| **35–49** | `fair` | 一般 | 有空可以留意 | 敛光 · 云厚光微 | `--ink-fair` 青灰 | 苍烟冷灰 |
| **0–34** | `dull` | 平淡 | 不建议专程等待 | 微茫 · 且待新晴 | `--ink-dull` 灰褐 | 灰褐 |
| **核心缺失** | `unavailable` | 暂无预报 | 不推断晴天，不给建议 | 缺 | `--ink-unavailable` | 中性米灰 |

纸面墨色在干燥纸面（`#fdfaf3`）与雨湿纸面上均须 ≥ 4.5:1，新增或调整墨色时必须重新计算。天幕主题色（`--score-*`）只用于天幕上的元素，不用于纸面。

> **核心原则**：指数是 0–99 的综合物理条件评分，严禁解读为绝对概率或使用“百分之百”等未经支持的词汇。

## 4. 微物理气象联动规范 (Live Weather Microphysics)

页面实体元素与自然天气的联动由真实 Open-Meteo 数据驱动（[js/journal-weather-engine.mjs](../js/journal-weather-engine.mjs)），**杜绝脱离气象实际的无因装饰**。

**装饰不是控件**：胶带、黄铜夹、印章、齿孔等纸面装饰一律 `aria-hidden="true"`，不设 `role="button"` / `tabindex`，不进入键盘与读屏顺序。指针点击可保留为隐藏彩蛋（吹风、引雷、暖阳），但不得承载任何功能，也不加提示文字引导点击。

## 5. 组件与排版系统架构

### 5.1 主手记卡片 (Hero Master Card)
- **容器布局**：相对定位，上缘挂置黄铜长尾夹与手撕齿孔条（均为装饰，见 §4）。
- **信息顺序**（DOM 与视觉一致）：
  1. **抬头**：日期 · 时段手记签；夜间附月相签条（真实按钮，打开月相详情）。
  2. **指数区**：`霞光指数 0–99` 标签、大号指数（档位墨色）与朱砂印章同行，下方一行“档位 · 行动建议”（同墨色、加粗）。
  3. **时间区**：事件时间、“日落/日出 · 方位 角度”（如“日落 · 西偏南 257°”）与倒计时同一行；下方是观赏窗口（起止时间、余晖峰值）与一条窗口示意条（竖线为日出/日落时刻，圆点为峰值）。
     - 霞光窗口：民用晨昏蒙影时长的一半在日落前开始，峰值在日落后半段蒙影，结束于民用昏影终；日出对称。日轮视角改为太阳仰角 6° 至触及地平。由 `viewingWindow` 计算。
     - 倒计时以窗口为准：“N 分钟后开始” → “观赏窗口进行中” → “本场已结束”。
  4. **评注区**：评语引文、另一视角分数切换按钮、数据来源与更新时间。
- **视角切换**：主卡只有一个视角切换入口——评注区的“另一视角分数”按钮（如“日轮指数 2 分 · 地平吞日 ｜切换”）。不再设置并列的霞光卷/日轮卷标签页，避免与顶部晚霞/朝霞切换叠成三层。
- **桌面端（≥861px）**：卡片为两栏，左栏指数区 + 时间区，右栏评注区，以竖向虚线分隔，避免宽卡片中部留白。
- **移动端（≤860px）**：单栏，指数与印章两端对齐；≤360px 不再需要特殊布局。
- **日期一致性**：时间、倒计时、分数、伴随指数、建议、线索与气象指标必须取自同一选中事件。切换研判视角或刷新同地点、同时段时保留日期，新的地点或成功切换晨昏时段后重置选择。

### 5.2 影响因素 (Factor Sheet)
替代旧版“天空线索”与“观测数据”两节（两者数字重复，且方格只给数值不给好坏）。
- 一张纸面清单，每行一个要素：名称与数值、对指数的增减（`+N 分` 绿 / `−N 分` 朱 / `±0 分` 灰）、理想区间示意条（绿色区段为理想区间，圆点为本次数值）、一句解释。增减幅度最大的两项名称加粗。
- 数据来自 `skyBreakdown` / `sunDiscBreakdown`：评分函数就是对这些增减求和，**展示与评分不可能不一致**。霞光以理想云况（高云 42%、中云 35%）的 89 分为基准，云况偏离即为扣分；日轮以 92 分为基准。
- 触发封顶（如低云与中云同时厚重）时，在清单末尾单独说明封顶原因。
- 区块标题右侧显示“基准 N 分 · 逐项增减”。桌面端（≥761px）两列排布。

### 5.3 未来 7 日 (7-Day Forecast)
- **本周最佳**：区块标题右侧是“本周最佳 · 周五 74 分 · 值得追”按钮（最高分低于 50 时改为“本周最高 N 分”），点击直接选中该日。
- **七日概览**（仅 <961px）：卡片上方一条 7 列分数柱，柱高与颜色按档位墨色，选中日描边、最佳日星期加粗，点击柱子选中该日；桌面端 7 张卡片已并排，不显示概览。
- **远期参考**：第 5–7 天数值预报可信度下降，卡片改虚线边、水彩试色淡化，档位文字后加“· 远期”，概览柱改为斜纹；文字对比度不降低。

7 日卡片统一采用三行结构，行内元素垂直居中：
- **第一行**：日期与星期（单行不折行）、右侧朱砂小印（与主卡同一档位表）。
- **第二行**：水彩试色条（档位色）。
- **第三行**：`tabular-nums` 大号分数（档位墨色）、档位文字与事件时间、一行评注。
- 不在卡片里放 emoji 图标；日轮视相只在主卡的视角切换按钮中出现。
- **视口适配**：桌面端（≥960px）采用 7 列并排实体票据展示；窄屏视口（<960px）采用原生惯性平滑横向滚动，带有视差渐隐边缘指示。
- **日期选择**：选择卡片只改变详情对应的事件，不移动七日列表的起点；高亮和 `aria-pressed` 跟随选中日期，重新渲染保留卡片的键盘焦点。

### 5.4 和纸票据弹窗与抽屉系统 (Stationery Docket Dialog & Sheet)
地点弹窗（`#places-dialog`）、月相弹窗（`#lunar-dialog`）与开发者观测台（`#dev-lab-dialog`）共用 `.paper-surface.paper-sheet`：
- **和纸票据形态**：米白底色，四周 1px 细虚线边框，顶部加贴撕边和纸胶带装饰。
- **篆刻标题印章**：标头左侧并置朱砂红印章（如“地”字印、“记”字印）。
- **指南针罗盘卡片 (Compass Specimen)**：当前设备定位卡片采用深色仿皮革/金属罗盘设计，右上角配朱砂小印。
- **搜索输入与列表**：搜索框采用羊皮纸内阴影输入槽；搜索结果与收藏行采用点划线分隔，鼠标悬停带有向右滑动与朱砂红微变动效。
- **滚动与关闭**：弹窗固定在视口中，内容超出高度时在纸面内部纵向滚动并隔离滚动链；标题和关闭按钮保持可达。原生模态弹窗打开时锁定背景滚动，关闭后恢复阅读位置，胶带装饰不依赖内容溢出纸面。
- **响应式抽屉断点 (760px)**：
  - **桌面端 (>760px)**：居中微倾角悬浮和纸票据卡，背景带温润天空磨砂遮罩。
  - **移动端 (≤760px)**：自适应为底部和纸抽屉（Bottom Docket Sheet），顶部露出实木质感拖动手柄（Drawer Handle），支持弹性阻尼跟手拖拽与滑动关闭。
- **收藏反馈**：移出收藏、撤销和错误反馈使用完整的局部纸面背景、墨色及焦点配色，不继承天幕或全局深浅主题的半套颜色。

### 5.5 字体与尺寸底线
- **字体族只用三类**：`--font-serif`（正文与标题）、`--font-num`（大号数字）、`--font-mono`（日期戳、时间戳、编号）。不使用日文明朝体，不在纸面混入系统无衬线。
- **字号底线**：可见文字 ≥ 11px（印章副字 ≥ 10px，属于图形）。新组件优先复用已有字号：11 / 12 / 13 / 14 / 16 / 18 及展示字号，不为单个组件新增半像素字号。
- **触控目标**：主要控件（顶部操作、时段切换、视角切换、7 日卡片）≥ 44px；小签条类次要控件视觉可更小，但须用伪元素把热区补足到 44px 高。
- **单位与符号**：温度用 `℃` 单字符，避免衬线字体下 `° C` 出现间隙。

## 6. 首屏渲染与 Zero-FOUC 抗闪烁规范

### 6.1 核心痛点与原则
**严禁冷启动白屏、严禁渲染瞬间露出旧深色或旧橙色背景**。用户点击打开应用的第一帧，视网膜感知到的必须是与当前时间吻合的纯净水彩天幕。

### 6.2 实现机制 (Synchronous Sky Hydration)
- [index.html](../index.html) 的 `<body>` 起始处内联一段同步脚本（零依赖，< 1KB），在任何可见内容之前执行。
- 脚本执行逻辑：
  1. 读取 `localStorage` 中上次的天幕主题（`firecloud:theme:v1`：昼夜、天气、档位、三段天色）与是否已有地点。
  2. 有主题缓存时直接沿用其昼夜；没有时按设备时钟 6:00–20:00 粗判昼夜（不计算太阳仰角，精确值由 `app.mjs` 加载后更新）。
  3. 写入 `body` 的 `data-state` / `data-light` / `data-weather` / `data-tier` 与 `--sky-top/mid/horizon` 变量，首帧即为上次天色。

## 7. 动效、可访问性与性能军规

遵循 Emil Kowalski 与 Apple Human Interface Guidelines 动效设计准则：

1. **严禁全局非特定 `transition: all`**：
   - 必须精确指定过渡属性（如 `transition: transform 200ms ease, opacity 200ms ease`）。
   - 彻底避免触发意外的几何重排（Reflow）与布局重算。
2. **复合图层与硬件加速**：
   - 高频与数据更新动画只用 `transform` 与 `opacity`；`filter`（尤其 `blur`）只用于低频的一次性天气特效，不用于数据刷新过渡。
   - 关键物理元素开启 `will-change: transform` 或使用 `transform: translateZ(0)` 独立复合层。
3. **严格尊重减弱动态效果 (prefers-reduced-motion: reduce)**：
   - 当系统开启减少动效时：
     - 关闭双层 Canvas 中的所有落雪、降雨、飞叶与光子飘飞。
     - 禁用强风抖动、闪电电磁频闪与便签翻折。
     - 所有弹窗入场使用即时 `opacity` 切换，不包含长距离位移。
4. **悬停与触控解耦**：
   - 桌面手札悬停翘起效果严格限定在 `@media (hover: hover) and (pointer: fine)` 作用域内。
   - 移动端触控保留按压微凹（scale 0.98）的真实触觉反馈。

## 8. 自动化验证与质量门禁

每次变更必须通过以下验证流程方可合并或交付：

1. **代码检查与单元测试**：
   ```bash
   npm run verify
   ```
   - `npm run check`：确保所有 ES 模块无语法错误。
   - `npm test`：运行 `tests/` 下全部单元测试（算法、档位分界、气象映射、物理边界）。
2. **多端视口布局真实校验**：
   - 320px：极限窄屏无横向破框与孤字。
   - 390px / 430px：主流手机端底部抽屉流畅度与主卡片手撕纸边缘比例。
   - 760px：抽屉与桌面浮窗临界断点平滑切换。
   - 960px / 1200px+：未来 7 日卡片 7 列规整排版与等宽数字对齐。
3. **离线与缓存完整性**：
   - 每次样式或逻辑更新必须同步递增 `sw.js` 的 `SHELL_CACHE`，并让 `index.html`、`app.mjs` 的 import 与 `sw.js` 的 `SHELL` 列表使用同一组 `?v=` 参数。

## 9. 代码组织

### 9.1 样式表
- **单一样式表、按组件分节**：`css/style.css` 依次为令牌与基础元素、天幕、顶栏与通用控件、欢迎页、加载面板、错误面板、时段工具栏、主卡、区块与影响因素、未来 7 日、弹窗与抽屉、页脚、纸面天气联动，每个组件只出现一次。节内先写基础状态，再写媒体查询与交互状态。
- **同一选择器只写一条规则**：不要在别处再写一条同选择器的规则去覆盖前面的值，直接改原规则。跨组件共用的选择器列表按组件拆开写。
- **交互态不靠先后取胜**：交互态（hover/active）与天气状态类可能同时作用于同一元素时，用更具体的选择器明确优先级，不依赖写在文件后面。
- **`!important` 只用于两类场景**：压过 `prefers-reduced-motion` 等全局 `*` 规则，或压过选择器更具体的通用规则。新代码优先调整选择器或直接修改原规则，不新增 `!important`。
- **不留死代码**：删除组件时同步删除它的选择器与 `@keyframes`。类名与 id 只来自 HTML 属性和 JS 字符串，可据此静态检查死选择器。
- **重构验收**：大范围样式调整时，用计算样式快照（多视口 × 欢迎/预报/夜间/弹窗/搜索结果/错误/加载 × 强制天气状态 × 强制 hover/active/focus）对比前后，差异须为零。

### 9.2 脚本模块
- `core/` 不依赖 DOM：存储与缓存、展示格式、预报会话（状态流转），在 Node 中有单元测试。
- `ui/` 每个模块负责一块界面，自己查找所需元素；`app.mjs` 只做创建与接线。
- 模块之间按普通相对路径互相引用，版本号统一由 `index.html` 的 import map 钉住；新增、删除模块或发布前运行 `npm run sync-modules`（发布时加 `-- --bump`），`tests/release.test.mjs` 校验 import map、Service Worker 预缓存与实际文件一致。
- 动画统一挂在 `frame-loop` 上，没有粒子或特效时不占用帧。
